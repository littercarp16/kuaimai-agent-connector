# Codex CLI原生共享协作

适用于快麦网页与 Codex CLI 同一会话的双向协作，连接器来源为 `provider:codex`。支持同版本的 `0.166.x`、`0.167.2`、`0.168.0`、`0.169.0`，以及 CLI `0.167.2` 搭配共享 daemon `0.168.0`、CLI `0.168.0` 搭配共享 daemon `0.169.0`。

## 接入顺序

1. 快麦连接器本身仍按[自动准备](automatic.md)由本机Agent/受信准备器复用或启动。**不启动第二个Codex或第二个快麦连接器**，不为接入重启现行daemon、改模型/审批/登录。纯CLI查询无协作意图不强启。
2. 只读`codex app-server daemon version`核验已运行共享daemon，连接器使用其中自有Unix Socket的WebSocket接口。没运行、版本不符或权限不安全就报告未接入；不执行daemon start/restart，不修改用户配置，不将proxy原始字节当JSONL。
3. 网页按Codex分组显示当前授权工作区内真实会话。对照原生`thread.id`（不是sessionId会话树根）与绑定元信息`nativeThreadId`；连接器对外使用`ses_codex_`命名空间。不能借列表中另一旧任务、其他来源的 sesID或自造generic任务发布当前成果。无法确认当前真实threadId就停止发布，不根据标题猜归属。
4. 新来源默认观察，不继承旧源控制。用户在会话设置明确授权后，才可在网页向同thread发送/停止/答问。新轮次与运行中补充由连接器分别走turn/start和带expectedTurnId的turn/steer；冲突、超时或未知结果不自动换轮次或重发。
5. 原生用户消息、公开回复和工具过程自动同步；技能用于遵守预览动作协议，不是靠Agent定时转述聊天实现双向。开始任务不意味着平台已建表/保存。没有真实新任务/网页applied回执时只报告已连接或已接收。

当前首版需从Codex分组明确绑定一次，不根据全局status广播猜测新用户意图，`followSessions:false`。绑定后的两端实时同步无需手工转发；已有WorkBuddy自动跟随仍按其实际能力工作。网页可选择现有会话或新建会话。附件和文件搜索按所选来源的实际能力启用。

## 问题、审批与停止

- 问题必须对应当前thread/turn/item及原RPC请求，答复不能伪装prompt。私密问题、未知表单留在原生客户端，不往网页回传。原端已答、断线或换实例后旧请求不可再答。
- 命令/文件审批与Questions分开。普通命令仅在完整上下文和版本支持时，可由用户明确做**本次**允许、拒绝、取消；文件审批首版只提供拒绝/取消，批准回原生客户端。不自动接受、不使用长期规则或扩大权限，不把脱敏/截断/遗漏移动目标的变更当可安全批准。
- 不支持的网络/额外权限/生物验证/动态工具请求留在原生客户端，不擅自响应。原RPC的resolved仅表示请求已处理，不证明工具或业务成功。
- 停止限定当前thread和turn；body等待或回执期间重连必须核对代次，不因迟到旧回执停止/污染新轮次。关闭网页只释放自身订阅，不停止Codex。

## 内容与成果

仅公开文本与受控工具详情；内部reasoning（包括summary流）不转发。普通正文/JSON/URL按既有保真与凭据过滤规则处理，技能/子Agent仅展示实际支持的公开内容，不承诺所有产品私有活动都可读。

预览使用本技能白名单协议，明确区分plan→逐块成果→ready；事件必须用当前核实来源。`accepted`只接收，`applied`是实际授权前端应用，不代表用户阅读/平台保存。“使用”仍是用户手动本机快照，不自动部署或写线上。

附件、文件引用、新会话和工具详情按当前来源显式capabilities启用；没有能力就如实说明，不能套用其他来源接口或通过普通文本偷偷代执行。只要支持范围不明确，不下载其它客户端或改审批来赶工。

## 不能类推的情况

独立Codex Desktop、IDE、`--no-daemon`或远端服务不保证与当前共享daemon同实例。共享历史可见不等于共享运行中事件；不得读私有数据库、扫描聊天目录、重启客户端或劫持独立会话。先核验官方端点/实例，失败就保持未接入。

本机元数据握手不等于发送/问答/停止已验收。真正模型任务会消耗额度并可执行原有工具，必须由用户明确发起；不要为了证明接通自动发测试prompt。生产代码、隔离fixture通过、客户端实际加载、用户网页回执分别报告。
